# 因子接口

因子继承 `utils.factor_base.FactorBase`，实现以下两个方法。完整骨架与合成数据检查见 [最小模板](FACTOR_TEMPLATE.md)。已有可运行的教学实现见 [momentum.py](../examples/momentum.py)。

| 方法 | 职责 | 输入 / 输出 |
|---|---|---|
| `_get_raw_data_for_factor(self)` | 声明读取字段并获取数据 | 返回长表，包含 `date`、`code` 和所需字段 |
| `calculate_factor(self, data)` | 计算调用者定义的因子 | 接收长表，返回日期 × 股票的数值宽表 |

输出必须为 `pd.DataFrame`：索引是唯一、升序的 `pd.DatetimeIndex`，名称为 `date`；列是唯一的字符串股票代码；值是数值，无法计算的观测保留 `NaN`，不要产生无穷值。普通和未过滤计算入口会拒绝 `None`、Series、数组、列表和标量并抛出 `ValueError`，不会丢弃索引后按位置转换、广播标量或将格式错误转成空结果。无结果应显式返回空 DataFrame。

## 返回格式兼容边界

标准输出是日期×股票宽表。基类的普通计算、未过滤计算和调仓窗口计算共用格式检查：

- 日期索引缺少 `date` 名称时补齐；字符串日期可转换为日期类型。保留已有行列对应关系，不展平宽表，也不要求单元格数等于原始记录数。
- 恰好包含 `date`、`code`、`factor` 三列的长表，按日期与股票键转换；原始行顺序可以不同。
- 旧单列值表仅在使用数值行索引、索引唯一且与原始数据行索引完全一致时按位置转换。新因子应直接返回标准宽表。
- 重复日期/股票列、缺失日期、非字符串股票列和无法判断含义的二维表会抛出 `ValueError`，不再以空表掩盖格式错误。空输出仍表示无可计算数据。

带日期/股票键的 Series 应由因子实现显式转换为日期×股票宽表或三列长表；无键数组应在生产它的代码中按已知维度绑定标签，基类不推断其含义。直接调用 `calculate_factor()` 不会经过基类格式检查，因此实现本身也应返回标准宽表。

## 股票分块的独立性约定

通用 `get_factor_values_unfiltered_chunked(chunk_size)` 默认整体计算。只有具体因子类自身显式定义 `STOCK_CHUNK_INDEPENDENT = True`，并使用基类未过滤入口时，才允许尝试 5 分钟股票分块；父类声明不会自动授权子类。该声明承诺增删其他股票不改变保留股票的因子值、日期范围或有效观测，不能用于截面排名、去均值、回归等跨股票算法，也不能只根据一次探针通过就添加。

已声明的因子仍需通过现有数据探针检查。`stock_chunk_mode='verified'` 仅表示已声明且探针通过，不是对所有数据的独立性证明。未声明或覆盖未过滤入口时保留完整股票和时间范围，记录 `fallback_full`，不自动转时间分块；这可能增加内存占用。股票探针、后续块计算及回退路径由同一外层 `finally` 恢复原股票列表；中断和异常继续传播。股票探针不通过时同样恢复完整股票范围并执行完整时间窗口计算，记录 `fallback_full`。通用时间分块回退已移除；现有因子专用分块方法保留自己的窗口及 PIT 约束。

两阶段 `_get_factor_values_from_prepared_stock_chunks()` 的 `prepare_chunk` 只提取本块特征，跨股票运算在合并后的 `calculate_prepared` 中执行。若因子有完整输入的最小行数要求，通过 `min_total_rows` 显式传入，并与完整计算入口保持一致；默认 `0` 不额外限制。该门槛按所有块累计原始行数检查，不能在预处理时对每块重复应用，否则调整分块大小会改变输出。 统一计算前会恢复完整的原股票列表，但仍保持本次未过滤计算模式。每次分块执行重新记录性能数据；空返回、异常和中断也会保留本次已完成的行数及已耗用时间，异常继续传播，退出时恢复原股票和过滤状态。

## 读取与运行

日频行情可调用 `_fetch_raw_data(fields=["close", "factor"], table_name="price_data_daily")`。数据库通常用 `stock_code`，基类读取后提供 `code`。按实际算法增加 `volume`、`money` 等字段；本地数据库必须已有这些字段。公开单因子 CLI 的教学 CSV 入口只构造其支持的行情列，不能据此假设任意字段均可读取。

通常通过 `get_factor_values(force_recalculate=True)` 运行。它负责读取、在启用时应用 PIT 复权、调用计算方法及整理输出。直接调用 `calculate_factor(data)` 只执行子类逻辑，不会自动读取数据库或复权，适合纯计算单元测试。

启用 PIT 时，非空输入只要包含共享复权实现处理的价格或成交量字段，就必须包含配置的复权因子列，缺列会明确抛错。空表及没有待复权字段的输入（如纯财务指标、仅金额）可原样通过；已存在的复权因子列仍接受原有有效性校验。

`get_factor_values_unfiltered()` 的性能记录为已执行阶段保留耗时，包括失败阶段；总耗时覆盖提前返回和异常退出。未执行阶段不填充为零。`pit_seconds` 表示复权函数调用耗时，不是成功复权标志。

先按 [README](../README.md) 运行教学示例。接入自定义因子时，复制示例分析配置，修改 `factor_file`、`factor_class`、`input_csv` 和 `output_dir`，再通过 `python -m tools.agent_harness.cli single-factor-analysis --config <配置路径>` 调用。配置内路径相对配置文件解析；命令行 `--output-dir` 相对当前工作目录解析。输出目录必须尚不存在。

## requirements 声明

数据需求是 JSON 配置，不是因子类里的同名方法。参考 [现有声明](../config/factor_requirements.json)：在 `factors` 下以类名为键，设置 `requirements`，再按频率填写字段和历史长度。

| 位置 | 含义 |
|---|---|
| `factors.<类名>.requirements.daily.fields` | 日频所需字段，包括价格复权需要的 `factor` |
| `factors.<类名>.requirements.daily.min_days` | 计算所需的历史日数，按算法依赖确定 |
| `factors.<类名>.requirements.5m.fields` | 5 分钟所需字段 |
| `factors.<类名>.requirements.5m.min_bars` | 所需历史 bar 数；不是自然日数 |

不提供通用研究窗口或表现阈值。长度应覆盖算法的滞后和预热需求；声明不会自动实现滚动计算，也不能保证数据足够或无前瞻。涉及基类按名称读取窗口的路径时，更新仓库 `config/factor_requirements.json`；聚宽构建时通过 `--requirements` 显式传入配置。构建器会据此计算取数窗口并检查频率，细节见 [聚宽打包](JOINQUANT.md)。

本模板只覆盖日频价格输入。5 分钟、多源或财务因子需要分别验证频率、数据可知时点和字段映射；公开单因子 CLI 不提供通用高频评估入口。复权、金额与成交量、缺失值及窗口约定见 [数据语义](SEMANTICS.md)。

本地基类使用 DuckDB：可提供 `duckdb_path`、版本化数据绑定，或内存 `duckdb.DuckDBPyConnection`。默认 `db_backend="duckdb"`；旧 `auto` 仅作为 DuckDB 别名，不做后端回退。`get_price_data()` 使用同一数据源。聚宽云端取数仍由 adapter 接管，不要求云端安装 DuckDB。

## 股票池

基类构造参数和实例属性使用 `stock_pools_by_period`，字典值为股票代码列表。旧参数和属性 `monthly_stock_pools` 仍可使用；实例的两个名称指向同一份映射。构造时只能提供其中一个参数。`JQFactorAdapter.run_factor()` 同样接受这两个参数名，不能同时传入。

固定股票池仍使用 `stock_pool` 和 `use_dynamic_pool=False`。预计算股票池使用 `stock_pools_by_period` 和 `use_dynamic_pool=True`，无需 `stock_filters`，也不会创建选股管理器；同时提供筛选条件时也以预计算历史为准。仅当没有提供预计算历史、需要按规则生成股票池时，才要求筛选条件并创建 `DynamicStockPoolManager`。

按规则生成股票池时，筛选条件/数据源验证失败或生成过程异常会中止因子构造，不会转换成空池继续运行。可正常读取但没有成员的指数快照属于合法空池。构造失败会关闭内部创建的读取器，调用方传入的连接仍由调用方管理。

同一字典的键必须全部使用一种规范格式：

- `YYYY-MM`：仅在指定自然月内生效。缺少某个月份时，该月没有可用股票，不沿用上月股票池。
- `YYYY-MM-DD`：从该日开始生效，到下一键日期之前结束；最后一期持续到输入数据末尾。首期之前没有可用股票。

原始行过滤、结果宽表过滤和 `get_stock_pool_for_date()` 共用上述区间规则。混合格式、未补零或非法日期会报错；空列表表示该期没有可用股票。整个动态池字典为空时，保留现有“不执行动态过滤”的行为；单日查询此时返回固定股票池。

固定池由共享过滤函数表示为无起止日期的区间，因此不会截断预热历史；固定池日常计算入口保持不变。内部未过滤读取和PIT回放临时关闭动态过滤时，也不会意外切换成固定池过滤。

结果阶段只把池外值设为 `NaN`，保留所有输入日期和股票列；原始数据阶段会删除池外记录。这里的日期键表达生效时间，不保证实际调仓频率为每周。PIT 调仓窗口回放有独立的取数与输出时点规则，不由这段结果过滤说明替代。

## 计算缓存

`cache_dir` 缓存因子计算结果。具体因子类必须显式实现 `_get_cache_inputs()`，声明全部因子参数和额外数据依赖；基类不再自动收集任意实例属性和类属性。未声明、返回 `None` 或输入不能可靠序列化时，继续正常计算，禁用这层缓存并记录 warning。子类需要显式重新声明或重写该方法，以免新增参数被父类的声明遗漏。

只依赖原始数据的因子可以这样声明：

```python
def _get_cache_inputs(self):
    return {"window": int(self.window), "scale": float(self.scale)}
```

返回值为字符串键字典，值使用 JSON 原生参数（包括嵌套字典和列表）或顶层 DataFrame。日期应显式转换为 ISO 字符串，NumPy 参数应转为 Python 标量；数组如确为独立参数，应声明其 dtype、shape 与列表内容。集合应排序后转换，路径字符串只代表路径；外部文件内容变化不会自动由路径识别。元组、非字符串字典键及未知对象等不能作为隐式转换的捷径。固定在源码中的常量可由源码摘要识别；可变类属性和模块全局参数必须在声明中读取其当前值。

如计算还读取事件表，必须在检查缓存前读取本次数据，并返回对应 DataFrame；本次 `calculate_factor` 应消费同一份快照。每次获取原始数据时应清理上次的事件快照，避免声明依赖时仍返回过期的内存数据。不能只声明表名、文件路径或无不可变保证的时间戳。读取依赖失败应抛出异常，不能用已有结果掩盖失败；无法确认完整依赖时返回 `None`。

基类额外纳入原始 DataFrame、框架日期/股票池/PIT设置、规范化的 StockFilter 条件、数据绑定、继承链与共享PIT实现源码及 pandas/NumPy 版本。DataFrame 使用流式 pickle protocol 4 的内容摘要，包含值、顺序、索引、dtype、类别信息和 attrs；序列化表示变化可能造成额外缓存未命中。日志、诊断计数器、连接和未声明的内部运行缓存不参与身份。外部辅助模块的实现变化不会自动被类源码摘要覆盖；应额外声明其版本或内容摘要。

新键使用 `factor-v3-` 前缀，不读取旧 v2 计算缓存；旧文件不会自动删除。命中只省去因子计算，不省原始数据和额外依赖的读取。`force_recalculate=True` 跳过结果命中并更新可用缓存，但不会自动清理其他层的取数缓存。未过滤回放、DuckDB取数缓存和合成层缓存有各自的规则，不受本接口自动管理。

`StockFilter` 的 `in/not_in` 条件若使用 `set/frozenset`，缓存身份会按成员的 JSON 表示稳定排序后记录，不修改原条件；成员须能以有限 JSON 值表示。列表、元组和条件列表保持原顺序。此处理仅适用于这些股票过滤条件，不改变 `_get_cache_inputs()` 对自定义参数的要求。

计算缓存先写入缓存目录内的唯一临时目录，文件完整写入并关闭后，通过 `os.replace()` 原子发布到正式 `.pkl` 路径。写入或替换失败时保留原缓存，普通失败只记录警告；正常异常退出会清理临时文件。进程被强制终止可能遗留临时目录，但读取器不会把它当正式缓存。此机制保证完整文件的原子可见性，不承诺断电持久性；同键并发写入由最后一次成功替换生效。

缓存命中前校验结果结构：必须是非空 DataFrame，使用名为 `date`、无 NaT 且唯一的 DatetimeIndex，股票列必须为唯一的非空字符串。不符合时记录警告并按未命中重新计算，成功结果通过原子保存替换旧文件；不尝试把错误缓存转换成合法输出。保留现有正常结果的顺序、时区、日内时间、数据类型、attrs 和全 NaN 情况。这是结构校验，不证明格式合法的数值一定正确。
