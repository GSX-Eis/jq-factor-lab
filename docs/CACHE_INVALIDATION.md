# 数据导入与缓存失效

## 契约

成功提交导入时，在同一 DuckDB 事务内更新 `meta.cache_revision` 的随机代号。
代号只标识缓存有效期，与输入数据的内容版本、实验绑定、模型版本无关。
读取器在命中缓存前读取代号；发生变化便丢弃相关缓存并重新计算。
查询或股票池计算结束后再次检查，发现中途更新则清缓存并报错，要求重试。
导入失败或回滚时，数据与代号一起回滚；没有“数据提交了但清缓存失败”的间隙。
已有库无需迁移：没有代号时使用旧源身份，首次受支持导入自动创建代号。

## 职责与 harness 边界

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 本地导入器 | 校验文件、写入行、在事务提交前更新代号 | 删除其他进程内存、删除研究文件 |
| 输入库发布器 | 校验 staging、检查父版本、原子发布数据与代号 | 改写已冻结的实验绑定 |
| 读取与缓存组件 | 命中前检查、丢弃旧内存结果、用代号区分磁盘缓存 | 绕过数据库锁、自动重跑整个研究 |
| harness | 组织命令、前置检查、冻结输入、核验结果、记录回执和恢复状态 | 保证任意自定义 SQL 的失效通知、把退出码零当成研究通过 |
| 输出清理器 | 按既有所有权和租约规则回收可再生缓存 | 清理模型、报告、冻结输入、复现证据 |

本仓库 `tools/agent_harness/cli.py` 是分析与合成的执行包装。
本地文件导入仍可直接调用 `data_pipeline.loaders`，缓存正确性不依赖 harness。
外部编排器可以先运行导入器生成 staging，再调用
`utils.input_store.publish_input_batch()` 发布正式输入库。
staging 自己的代号不代表正式库已经更新；正式库只在发布事务提交时失效。
`meta` 中的代号不属于待发布的业务表。

写入需遵守 DuckDB 的连接和进程锁规则。长期持有只读连接的研究进程应先结束
读取会话，编排器等待数据库可写后再导入。缓存协议不是跨进程强制关闭连接机制。
借用连接不会被缓存组件关闭、提交或回滚；调用方事务仍由调用方管理。
本协议检测一次读取/股票池调用中的代号变化，不替代整场研究的冻结输入协议。

## 已接入的写入边界

- 行情、因子 CSV、指数成分与通用辅助数据导入：共用 `atomic_import`。
- 原始财报导入：在已有提交点更新代号。
- 输入版本迁移、输入批次发布、交易日历发布：共用 `write_store` 提交。

有些 CLI 包含多个独立导入事务，代号按每次成功提交更新，不把整个命令误称为
单一原子操作。已经提交的分区不会因后续分区失败而回滚。

## 缓存范围

- DuckDBAdapter 的行情、因子及通用面板缓存。
- 股票池的字段、指数成分和月度/周度/指定日期结果，包括复用的管理器实例。
- FactorBase 的计算缓存。收益缓存还根据实际价格内容与交易日历生成身份。
- 合成原始/处理后因子缓存和预处理面板缓存。

磁盘缓存以代号进入身份；旧文件立即停止命中，物理回收仍走原来的受管清理流程。
显式只读且校验哈希的冻结快照属于研究输入，不自动删除或切换版本。

## Parquet

内置行情、因子、指数导出使用根目录 `.cache-revision.json`：导出前标记 `pending`，
成功后标记新代号为 `ready`，并用文件锁阻止同目录的多个发布者交错写入。
完整导出会先清除目标数据集的旧 Parquet 分区，防止已经删除的月份仍被读回；
导出失败时源 DuckDB 保留，可重新导出。
导出失败会抛错并保留 `pending`，读取器拒绝将半成品视为有效数据；修复后重跑导出。
DuckDB 导入和 Parquet 导出是两个操作，后者失败不会撤销前者已经提交的数据。
双来源策略也检查 Parquet 状态，避免数据库为空时回退到未完成的导出。
外部没有发布标记的目录仍可读取，但关闭跨调用的应用缓存和派生因子磁盘缓存；
不承诺检测未遵循发布协议的并发文件修改。

## 自定义写入与维护

推荐在自己的写入事务中调用 `advance_revision(conn)`，或直接复用
`data_pipeline.loaders._transactions.import_transaction(conn)`。不要嵌套事务。
维护完成后也可以显式失效：

```bash
python -m utils.data_revision --database ./data/market.duckdb
```

此命令只更新代号，不删数据、不自动迁移版本。手工 SQL、直接替换数据库文件、
改动有标记的 Parquet 文件但不更新标记，均不在自动通知契约内。
这些维护操作应先停止读取会话，完成后再失效或创建新读取器。
