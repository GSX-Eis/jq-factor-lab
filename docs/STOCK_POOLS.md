# 统一股票池接口

所有周期共用 `DynamicStockPoolManager.get_stock_pools_for_period()`。管理器内部只保留一套 `_select_stock_pool()`，负责候选集、基本面条件、状态条件、指数成分、百分位、排序和数量限制。周期只决定调用它的日期。

## 使用

```python
pools = manager.get_stock_pools_for_period(
    '2026-01-01', '2026-06-30', filters,
    schedule={
        'unit': 'month',
        'interval': 1,
        'session': 1,
        'short_period': 'last_session',
        'include_previous': True,
    },
    sort_by='val_market_cap', ascending=True, max_stocks=100,
)
```

`FactorBase` 接收同样的 `pool_schedule` 字典；合成配置使用 `stock_pool.schedule`。两者均将其传给统一入口，显式 schedule 优先于旧 rebalance_schedule/rebalance_period_months。

- 每周第三个交易日：`{"unit":"week","session":3}`。
- 每月首个交易日：`{"unit":"month","session":1}`。
- 每月最后一个交易日：`{"unit":"month","session":-1}`。
- 每季度首个交易日：`{"unit":"month","interval":3,"anchor":"2026-01-01","session":1}`。
- 每两周：`{"unit":"week","interval":2,"anchor":"2026-01-05","session":3}`。
- 指定月份：`{"unit":"month","months":[5,9,11],"session":1}`。它只定义日期，不声明财报是否已披露。

interval 必须为正整数；大于1时需固定 anchor。session 从1开始，也支持倒数位置，不能为0。短周期默认选最后一个交易日；short_period 可以选择 skip 或 raise。所有日期来自独立的数据库交易日历，不能用工作日或行情行补猜。

补充期初有效池时同样遵守 short_period：raise 不允许跨过此前不足指定交易日数的调仓周期，静默沿用更早的池；skip 才允许跳过。若短周期之后已有一次正常调仓，则更早的短周期不影响本次期初池。未请求期初池时，不检查查询范围之前的短周期。

显式 schedule 默认 boundary=complete_period：先在完整自然周/月中选择日期，再裁剪查询区间；日历覆盖不足报错。include_previous 默认 true，在区间开始时已经有生效股票池的情况下，附带此前最近一个调仓日。缺少该历史周期的日历覆盖时要求补齐，不伪造期初股票池。只需要区间内新调仓事件可设 false。

输出始终是实际生效日 YYYY-MM-DD → 有序股票列表。该池从键日期生效至下一键之前；空列表是有效空池，不能解释为不限制股票。不会返回 YYYY-MM 键。

## 现有周度配置的兼容边界

已有 `rebalance_schedule='weekly'` 不改配置即可继续使用。它经过同一个日期生成器与选股器，但沿用原 boundary=query_window、include_previous=false、每周第三个交易日/短周末日的设置。这保留旧查询区间截断半周时的日期结果。不要将这种日期列表误称为与查询窗口无关的固定周调仓表。

从旧 weekly 改用显式 `schedule={"unit":"week"}` 会启用完整周期和期初池规则，半周边界可能变化。这个变更需要单独核对，不会在升级代码时自动发生。

月度、季度、report_based 不再使用“滞后月份月末统一快照”。它们在实际生效日调用与周度相同的选股规则，属于明确的策略语义变化，旧月度研究结果不承诺相同。旧 quarterly 名称仍使用 rebalance_period_months（缺省1）；明确季度请配置 month/interval=3/anchor。旧 report_based 映射到5、9、11月首个交易日。非周模式显式 lag_months>0 现在报错；None/0 接受但不执行月度快照滞后。旧周模式仍忽略原本未使用的该参数。

退役方法：get_monthly_stock_pool、_get_weekly_stock_pool_with_lag、get_stock_pool_for_specific_date。调用方改用统一期间入口；需要某日直接计算时内部使用 _select_stock_pool，不提供另一套选股实现。get_weekly_run_dates 仍供现有日期消费者使用，不执行选股。

旧月末辅助方法 `get_last_trading_day`、`test_filter_individually` 已移除，仓库内无调用方。月末调仓使用 `schedule={"unit":"month","session":-1}`；诊断当前选股过程使用统一筛选日志，不再按自然月末另查一套条件。

## 数据时点与字段配置

默认规则集中在 `config/stock_pool.json`，管理器可用 pool_config_path 指定替代文件。配置在创建管理器时读取，修改后应新建管理器；合成中已缓存的管理器需要清理对应实例缓存/重启任务。

为保持现有周度结果，默认规则如实延续原逻辑：

- 基本面字段按配置的前缀/显式字段集合识别；候选股票与基本面条件使用严格早于 T 的最近**有数据日**。这并不保证是日历上的前一个交易日。
- 基本面快照日期统一返回`YYYY-MM-DD`，日频DATE或午夜TIMESTAMP经DataFrame读取后不会把`00:00:00`带入日志和后续日期条件；无历史数据仍返回空值并由missing_previous策略处理。
- 如果此前没有基本面快照，默认 missing_previous=same_day，使用 T；这保留旧行为，不代表当天所有字段在开盘时已经可知。需要严格拒绝可设 raise。
- 状态条件与指数成分使用 T，状态比较中的 close 通过字段别名配置映射到 open。排序字段与百分位不套用这个别名，延续原周度规则。
- 百分位先执行普通条件与指数交集，再按配置顺序在剩余候选中计算。基本面字段用此前快照；价格表字段用 T；其他基本面表字段延续此前快照规则。它不是全市场排名，也不承诺严格的股票数量比例。
- `selection.source_priority`集中定义来源顺序：普通状态条件默认`["fundamental", "price"]`，非基本面百分位默认`["price", "fundamental"]`，排序默认`["fundamental", "price"]`。基本面条件/基本面百分位固定使用基本面表。每个条件独立解析，来源不会因添加其他条件或排序字段而变化。
- 状态条件先应用左侧字段别名，再校验完整条件所需列并选表。例如`close < high_limit`按`open`和`high_limit`选表，不要求原始`close`存在。单个条件所需字段必须在同一张表内；两表均满足时按配置优先级选择，不自动跨表拼接。排序与百分位不应用状态别名。
- 数值比较右值支持数值、数值字符串、简单字段名（例如`high_limit`）以及显式单引号字符串字面量。布尔字段保留原字符串/整数兼容；`in`、`like`、前缀匹配中的字符串仍按原字面值处理。复合SQL表达式不属于此条件接口，明确报错。
- `in/not_in` 的值必须是非空 `list/tuple/set/frozenset`，JSON配置使用数组。单个代码写成 `["000001.XSHE"]`，不能直接传字符串，避免被拆成字符；字典、生成器和空集合不接受。集合元素的原有SQL表示不变。
- 集合元素、LIKE模式及前缀中的单引号由SQL字面量引用函数转义。`like/not_like`保留SQL通配符语义：`%`匹配任意长度，`_`匹配单个字符；`starts_with/not_starts_with`按字面前缀处理，前缀中的`%`、`_`、`!`不再被解释为模式。
- 前缀条件只接受字符串或非空字符串列表；多个正向前缀取OR，多个反向前缀取AND。空列表或非字符串元素在查询前报错；空字符串前缀仍匹配所有非NULL字符串，保留原有行为。普通比较中的字段引用和显式SQL字符串字面量契约不变。
- 布尔字段的 `==/!=` 只接受整数 `0/1`、`False/True`、字符串 `"0"/"1"/"false"/"true"/"False"/"True"`，包括对应的NumPy整数/布尔标量。浮点参数（即使是 `0.0/1.0`）及其他非法值在生成SQL前报错，不能把 `!= 2` 静默解释为“假”。布尔数据列仅支持BOOLEAN、整数和上述文本表示，不支持浮点存储；本接口不转换数据库字段类型。合法布尔比较不将NULL当作假值。
- 只有已读取schema缺少所需字段时才尝试下一配置来源；源表缺失、读取失败或目标日期缺数据不会触发静默换源。普通条件查询无匹配记录仍表示空池；百分位没有可计算值会报错。
- 旧自定义股票池规则文件缺少`source_priority`时，从随代码分发的默认配置继承该新增部分，不改写用户文件；原调仓参数、筛选条件和基本面分类规则保持有效。配置改动后需重新创建管理器。

此项重构没有替代数据生产端的可得时点契约。尤其不能据此声称 T 日所有字段都适合盘中交易；更严格的 PIT 规则应单独变更、验证。

## 错误、缓存与复现

缺字段、非法/倒置区间、超界百分位、查询错误、没有候选快照或没有可计算百分位值都报错。合法条件筛选后为空仍返回空列表。排序只在实际来源表上执行；过去排序失败后忽略排序的行为不再保留。合成入口也传播异常，避免把失败当成全市场。

选股缓存以实际日期、条件、排序、上限和取数策略为键，与周期解耦，使用已有输入代号失效机制。自动分析股票池快照加入契约与策略配置身份，旧自动缓存失效；显式冻结并带哈希校验的历史快照不改写。字符串/前缀修复将自动快照契约从`resolved-selection-v2`更新为`literal-filters-v3`，避免复用旧匹配规则的结果。筛选日志同时记录原条件、映射后的实际条件、使用表和日期。

验证包含旧周度合成数据输出基线、短周/半周、完整周期与期初池、跨年锚点、月末/季度、相同日期不同频率结果一致、失败传播、导入缓存失效以及 FactorBase/合成入口配置转发。

## 筛选诊断日志

设置 `QUANT_DEBUG_OUTPUTS=1` 并绑定 `QUANT_DIAGNOSTICS_DIR` 后，选股器将当前统一格式追加到该目录下的 `pool_filter_log.txt`。未绑定目录时底层输出到空设备，不生成文件。仅完成实际计算时记录；缓存命中和计算中途失败不产生新的选股日志，文件写入失败只警告，不改变选股结果。

日志显示调仓日期、实际基本面快照日期、原条件、实际条件、来源表、筛选日期、百分位阈值与前后数量。移除列表标为 `REMOVED_SAMPLES (样本数 of 移除总数)`，每步最多20只；最终数量包含排序及数量上限的影响，但这两步目前没有独立明细。基本面快照日期不再标为T-1，避免误认为一定是前一交易日。

日志只接收统一选择器的 `trading_date`/`fundamental_date` 和 `removed_samples` 格式，旧月度 `date`/`year_month`、`removed_stocks` 回退已删除。百分位helper仅返回阈值信息，移除数量及样本由统一选择器记录。

## 来源解析修复的兼容边界

2026-10-28修复了按原字段选表后才映射状态字段、以及其他条件触发行情schema探测时百分位来源改变的问题。默认优先级保留普通条件/排序的基本面优先规则；非基本面百分位固定行情优先。两表同名且数值不同时，旧百分位的不稳定结果不能作为兼容承诺。需要固定到基本面来源时，可在自定义规则中把`source_priority.percentile`设为`["fundamental", "price"]`。百分位仍按顺序在剩余候选集内计算，阈值公式、调仓日和数量截取不变。历史冻结配置、结果及显式股票池快照不会被重写。


## 生效日成员解析接口

`utils.stock_pool_membership.StockPoolMembership` 为需要严格成员契约的调用方提供独立接口：

```python
from utils.stock_pool_membership import StockPoolMembership

membership = StockPoolMembership({
    "2026-01-05": ["000001.XSHE", "000002.XSHE"],
    "2026-01-12": [],
})
filtered = membership.filter_wide(values)  # index=日期，columns=股票
sql_members = membership.daily_frame(trading_dates)  # date、stock_code
coverage = membership.coverage(trading_dates)  # has_pool、member_count
```

映射必须非空，键必须为补零的有效`YYYY-MM-DD`字符串，成员必须为无重复、非空股票代码字符串组成的列表或元组；股票代码含首尾空白会报错，不自动修剪。某个生效日的`[]`表示明确空池；缺少整个历史映射会报错。成员按`[生效日, 下一生效日)`使用，最后一期延续，首个生效日前无成员，不回填未来股票池。

`filter_wide`保留原行列和顺序，包括全NaN列，只把池外单元格设为NaN，不改调用方输入；重复股票列报错。`daily_frame`仅展开请求的日期批次，每个日期/股票组合唯一，要求日期归一化后升序且无重复。日期须可解析、无NaT且无时区；拒绝整数、浮点、布尔等数字日期，避免被解释为时间戳偏移量。本接口按本地自然日期解析，不查询交易日历。空批次返回带明确日期/股票类型的空表，仍可注册到DuckDB。

`coverage`说明预期成员数，不代表实际行情完整率，也不补价格、不填零、不设新覆盖率阈值。历史收益或滚动基准需要入池前数据时，应先计算历史序列，再按当期成员过滤。宽表按成员区间处理，不额外创建全历史同形布尔矩阵；SQL调用方应传入当前日期分块。

这是供调用方明确接入的新接口。现有`apply_date_level_pool_filter_to_wide_df`保持原契约，尚未进行全仓替换。长表helper仍独立实现，支持历史`YYYY-MM`及可解析日期键，并按实际日期排序；缺失历史、重复生效日期、非法或重复成员、缺少date/stock_code索引层会报错。某期`[]`合法，池外行删除，原行序、值及重复观察记录保留。股票索引仍按原行为临时转字符串匹配，不改返回索引。


合成入口`apply_dynamic_stock_pool_filter`的`start_date`、`end_date`可独立省略：仅从面板推导缺少的一端，保留显式传入的另一端。两端都提供时直接转交股票池管理器，两端都缺省时使用面板日期范围。参数控制股票池生成，不负责裁剪因子面板；未启用过滤或面板为空时仍直接返回输入。

`build_stock_filters`在初始化基础条件管理器前校验自定义配置：`stock_pool`须为映射，`filters`须为列表或元组，每项须为映射且`field`、`operator`为非空字符串。错误包含条目位置，不再静默跳过缺失条件。省略`filters`或显式`[]`仍表示没有自定义条件；合法条件原顺序不变，基础条件仍排在最前。操作符支持范围、值类型及数据字段仍由后续选股校验，不在构造函数重复实现。

`get_all_pool_stocks`只汇总请求范围内各期成员的并集，不接收`skip_months`。旧参数仅用于统计日志，移除后股票并集及选股规则保持不变。合成配置中的`calendar_filters.skip_months`和`apply_to_training`、`apply_to_evaluation`、`apply_to_backtest`继续由对应业务阶段消费；不能通过删除跳过月份的池生效日来代替日期过滤，因为其成员可能延续到后续未跳过的日期，预热读取也可能仍需要这些股票。

预测期入口`compute_predict_period_dynamic_pools`复用`build_stock_filters(include_basic=False)`：保留原来的“只用自定义条件”策略，非法配置明确报错。日期仍为训练结束日加1自然日开始，再加配置的自然日偏移量作为结束日；默认周度和现有上游截断规则不变。未启用动态池返回`None`；启用后有交易日却没有生效期时抛错；显式某期`[]`保留为空成员集合。若整个窗口在本地交易日历中都是休市日，返回`{预测开始日期: set()}`表示该窗口没有可预测成员，避免把合法的休市尾窗误判为选股失败或放开过滤。

### Top-K 候选池的空结果

`compute_dynamic_pools_for_topk` 在关闭动态过滤时返回 `{}`；启用后如生成器没有返回任何生效期，则用同一交易日历检查请求范围：有交易日时报错，纯休市区间返回 `{开始日期: []}`，避免回测器将空映射理解为不限制候选股票。已有非空映射保持原样，包括明确为空的某期成员列表及股票顺序。

该入口不接收 `skip_months`；跳月规则由回测器的 `calendar_filters` 单独处理，候选池保留完整的生效历史。候选池的 `max_stocks` 与最终持仓的 `top_k` 分属两个步骤。

### 训练与评估的跳月过滤

`apply_skip_months` 对非空且启用跳月规则的 DataFrame/Series 校验日期：多层索引必须且只能有一个 `date` 层；单层索引允许日期类型或可解析的日期字符串。不接受数字日期、缺失日期/NaT 或无法解析的日期。失败直接抛错，不能返回未过滤数据；合法输入保持原索引、行序和数值，仅按位置删除命中规则的行。None、空对象或未设置规则时保留原有无操作行为。规则解析与回测清仓另由相应模块负责。

跳月规则由 `parse_skip_rules` 严格解析：`None`/空序列表示不跳过；容器须为可迭代的规则集合（JSON使用数组），不能是裸字符串、字节串、字典或标量。条目只接受1—12的整数/整数字符串或合法的`MM-DD:MM-DD`窗口，拒绝浮点与布尔值；非法条目携带位置报错，不再警告后丢弃。窗口支持空格、补零、跨年、重复去重；按闰年校验月日以允许02-29，不接受02-30等不存在的日期。合法配置的解析和匹配结果不变。

调仓解析会对最终合并后的 `unit` 统一校验：显式配置和旧模板都只能使用 `week` 或 `month`，缺失或拼写错误会在查询日历前报错。旧 `quarterly` 的月份间隔、固定锚点，以及旧 weekly 的查询区间边界语义保持不变。

按期计算因子时，显式空池（例如 `"2024-01-05": []`）仍是有效期边界，表示从该日起到下一期不生成成员信号。日频模式必须在该边界结束上一期，并在输出起点位于空池期间时沿用空池状态，不能退回更早的非空池。计算时跳过空池本身；调仓单点模式仍不为空池生成信号。

按期计算读取的非空原始表必须有可解析且非缺失的 `date`，以及非缺失、非空白的 `code`。校验失败直接抛出 `ValueError`，不删除坏行后继续计算，也不将缺失股票代码转换成字符串参与历史窗口选择。合法输入的日期转换、股票代码字符串化和排序保持原有规则；原始表不会被原地修改，失败时临时取数范围及股票池状态仍会恢复。

按期计算的输出先经过统一 DataFrame 契约校验，再判断是否为空；空 Series、None 等不能表示正常无结果。非空输出归一化到日期零点后，每日必须只有一行，否则明确报错，不自动选择或聚合同日的多条输出。每天只有一个时间戳仍按原规则归到当天，且不原地修改计算函数返回的表。`combine_duplicate_dates` 只处理不同期输出合并时的日期重叠，不放宽单次计算的每日唯一要求。
