# 数据与评估语义

本文说明接口约定与调用者需要确认的边界。因子实现见 [因子接口](FACTOR_INTERFACE.md)，本地文件字段见 [数据导入](DATA_IMPORT.md)，云端输入与打包见 [聚宽说明](JOINQUANT.md)。

## 日期与股票键

- 日频 `date` 表示实际交易日，不人工补齐周末或节假日。分钟输入保留 bar 时间，不能直接截成日期后当作唯一键。
- 本地 CSV / 数据表通常使用 `stock_code`；因子计算长表使用 `code`。同一频率下 `(date, code)` 必须唯一；重复记录应追溯来源或明确聚合，不能随意保留最后一行。
- 股票代码使用字符串，保留前导零和市场后缀。跨来源连接前先统一标识，不能假定不同市场的相同数字代表同一证券。
- 先统一交易所时区和 bar 时间含义，再转换为接口使用的无时区日期或时间；不要通过直接删除时区来掩盖时差。日频模板只接受无时区、无盘中时间的交易日期。
- 财务 `end_date` 是报告期，`pub_date` 是可知时点的重要输入。按报告期直接连接到历史行情可能引入未来信息；导入保存日期，不自动保证所有查询已实现时点过滤。

## 复权、金额与成交量

行情字段 `factor` 是累计价格复权因子，不是策略因子分数。公开单因子 CLI 在该列缺省时使用 1；只有来源确实无需复权时才能这样解释，不能把缺失的真实复权信息当作“无公司行动”。

`FactorBase` 使用 [共享 PIT 实现](../utils/pit.py)：按股票排序，以输入窗口内最后一个有效复权因子为锚点（部分调用路径可显式传入锚点）。设比例为 `r = factor / factor_end`：价格乘以 `r`，`volume` 除以 `r`，`money` 保持不变。有效行情行的复权因子必须为有限正数。非空输入含价格或成交量列时，缺少整列 `factor` 会抛出 `ValueError`（`pit_factor_column_missing`），因此价格因子取数时应显式声明该字段。空表直接返回；不含任何可调整价格或成交量列的输入（例如仅成交金额）可在缺少 `factor` 时原样返回。公开 CLI 缺省填 1 是其入口行为，不是该底层函数的回退。

`money` 表示成交金额，`volume` 表示成交量，二者不能互换。来源的币种、股数/手数单位须由导入者确认。用 `money / volume` 构造价格时，应先统一单位并明确零成交量、缺失值和复权阶段；不要把原始价格与复权成交量混用。adapter 中 `amount → money`、`turnover → volume` 是特定输入约定，不能套用于所有外部供应商。

直接调用 `calculate_factor(data)` 不会自动复权。不要对已复权价格再次应用相同比例。日频 CLI 的评价标签使用 `close * factor`，与基类的窗口锚点价格不是同一数值尺度。依赖绝对价格或成交量的因子尤其需要检查两条路径。

窗口末端锚点不等于自动实现逐日历史重放。若向整段历史追加未来数据导致锚点变化，历史输出可能受到影响；需要逐时点截断、统一锚点策略并做前缀一致性测试。复权本身也不能替代其他输入的可知时点校验。

## 缺失值、排序与窗口

- 缺失价格、停牌、尚未上市和不足预热期不能统一填成零。保留 `NaN` 并记录算法采用的有效样本规则；零成交量只有在来源明确表示实际零成交时才是有效观测。
- 不使用未来值反向填充历史缺失。前向填充也需要定义最长间隔、跨交易日边界及字段是否允许延用。
- 计算前按股票与时间稳定排序，逐股票计算时隔离分组。宽表以日期排序后滚动；避免把上一只股票的窗口接到下一只股票。
- `rolling(n)` 表示 n 行观测，时间窗口如 `rolling("7D")` 表示日历时间。宽表中的缺失 bar 仍占行；长表删掉缺失记录后再逐股票滚动可能得到不同结果。明确 `min_periods`、边界包含关系及聚合分母。
- `shift(1)` 的含义取决于所在轴与日期序列；不能将“一行”无条件解释为“一自然日”。跨日高频窗口还需要交易时段与 bar 数约定。
- 横截面排序、标准化应基于该时点可用股票，并明确缺失和并列处理。数据库返回顺序不能作为排名的隐含输入。

## 评价与运行边界

- 信号日期为 T，执行滞后为 L，持有期为 P；标签是 `price[T+L+P] / price[T+L] - 1`。尾部没有完整价格窗口的观测不参与相应周期评价。
- `AlphalensRunner.run` 与 `run_analysis` 使用相同的执行滞后和真实交易日口径；后者省略 periods/quantiles 时继承实例设置，不延长价格序列。
- IC 使用原始因子值计算 Spearman 相关，不加随机扰动。分层仅在当日截面计算，同值保持在同组；边界重复时组数可能少于请求值，常数截面跳过。追加未来数据不会改变历史分组。
- CLI 不模拟开盘成交、滑点、手续费、涨跌停或仓位，因此 IC、分层收益不能当作可交易组合收益。
- 底层 Alphalens 适配器在分析失败时可能返回空的占位结果；公开 CLI 会拒绝没有有效日期 IC 的结果并返回非零退出码。
- 合成算法保留各自的时间划分、预处理与交叉验证接口，限制见 [算法合成](SYNTHESIS.md)。
- 缓存中的 Pickle 仅用于自己生成的可信文件；不要载入他人提供的缓存。
- DuckDB 版本固定为 1.5.3，以匹配版本化数据指纹契约。


## 成交额与空 bar

本地日线因子取数在 PIT 前使用明确的 paused 状态：paused=1 且 money=0
转为缺失，保留正常交易的零金额、非零金额和既有缺失值。即使只请求 money，
也会读取 paused 后再移除这个辅助列，因此窄字段和宽字段遵守相同规则。
自有日线金额数据源需要提供 paused；底层原始数据读取接口仍返回存储值。

分钟线不以 volume=0 推断停牌。只有来源明确提供 paused 时才应用同一空额规则；
没有 paused 的分钟来源保留有效 factor 的零金额。价格锚点遵守同一观测规则。
本版本的金额语义为 source-money-v3；新缓存身份不覆盖旧结果。
本地真实日线抽样已验收，认证聚宽日线/分钟逐字段对照尚未验收。
